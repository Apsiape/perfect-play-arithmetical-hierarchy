# Finite checks: details

This file accompanies *A trace costs one quantifier: the exact complexity of perfect play in nonlocal games*. The paper's appendix
"Software checks" gives the one-page summary; `README.md` gives commands, dependencies and the folder table. This file holds the detailed
descriptions that were previously printed in the paper's reproducibility and compiler-validation appendices. Paper equations are named by
their LaTeX labels (for example `eq:nested-A4`), which are stable across versions; printed numbers may change.

Finite computations support the written proofs. They do not prove infinite-dimensional existence or extraction, compactness, the general
compiler, the Higman and HNN embedding theorems, the classification of type-III factors, or any hardness reduction.

## 1. Running everything

From a copy of this directory run

    python -B run_all.py --output-dir DIR

with `DIR` new or empty. The runner writes logs and results to `DIR`, regenerates the nested cores there, compares fresh counts and hashes
with the shipped records, and fails if any check fails. Add `--full-counts` to repeat both large full-game question counts. All suites run
from a relocated source copy. `SHA256SUMS` identifies every bundled file apart from itself, with relative paths and LF line endings.

Dependencies: the tree-and-clock checker needs NumPy; the communication suite needs NumPy, NetworkX, SymPy and mpmath; the nested checks
also use SymPy and psutil; the capacity checks use CVXPY with an SDP solver. The exact parity certificates use SymPy and rational
arithmetic.

## 2. Spatial suite (`spatial/`)

The numerical tree checker builds the truncated Fock model, Weyl pair, coordinate increments, clock, counter and exact-return candidate of
Sections 5-6 of the paper. Its pulse-driven cellular automaton is a small front-and-mark model; it is not an implementation of every
Turing-machine decoder used by the reduction. The checker tests the creation and range identities, modular scaling, endpoint recurrences,
clock and reader equations, tableau propagation, centralizer commutators and top-depth defects. The four diagonal isometry equations fail
exactly at the top depth, as predicted by `eq:fourdefects`; every other reported residual is at floating-point precision. The analytical
top-depth mass is `eq:topmass`.

The primitive-phase checker tests the existence of a good primitive phase for every prime below 4000, and tests the chord lower bound
for primes below 400. Its trigonometric evaluations use floating point. The good-phase lemma (`lem:goodphase`) is the proof for all primes.

The independent exact tree suite checks ten models, depths 0 through 4 and clock orders 2 and 3, with 2000 exact checks in total.

A separate minimal compiler instance has four bridges and one modular isometry, but no transported endpoint labels. It has 748 rational rows
and 27 991 questions per party. Its independent structural audit checks 77 750 bindings, 11 652 column-graph rules, all 748 row expansions,
333 scalar pair contexts and 2472 forbidden events of the original game. It does not instantiate the full ten-label computation compiler.
The worked tableau of the paper (`tab:toy`) is regenerated by the suite and compared with the paper line by line.

## 3. Type suite (`types/`)

The program uses exact rational identities for finite binary trees through depth 7, reader stand-ins through depth 4, an actual
source-lifted graph residual with the scaffold and qutrit density, finite shift truncations with their top boundary defect, and chain
scaffold masses through five bridges. It uses randomized finitely supported group elements with a fixed seed for the group law
`eq:model18`, and numerical entropy and rotation checks.

An exact-fraction enclosure certifies the golden-mean value at y = 1, the y = 2 comparison, and the rational base of the induction that
covers every y >= 3 in the rotation margin `eq:margin` (paper appendix "An exact rotation margin"). The floating sweep over 1 <= y < 4000 is
supplementary.

The Boolean profile core tests every reduction of the directional-difference theorem (`thm:differences`) with unspecified coordinates
treated adversarially, and enumerates all 7581 monotone five-input functions for an alternative input collection. Exact checks are
distinguished from floating-point checks in its output.

The finite stand-in is not a representation of an arbitrary finitely presented group G_e or of its HNN extension. It tests the level reader
and terminal algebra with an explicit balanced involution. Existence of the actual finite von Neumann algebra for any good depth rests on
the HNN normal-form theorem and the regular representation (`lem:hnn`).

## 4. Communication suite (`zero-error/`)

The magic-square graph has classical independence number five and a six-message entangled code. The flagged-magic-square graph has fifty
vertices, classical independence number nine and a ten-message entangled code. The reverse map of the trace-class correspondence
(`thm:correspondence`) is also tested after a noncommutative row-and-column scrambling. These examples check the implementation of the
finite correspondence already proved by Mancinska; they are regression checks, not new results. The naive forward marginal D^2 is tested
as a negative control. Floating-point matrix checks use explicit tolerances.

The exact script checks 4n+1, 6n+1, the cover constant c_n, the normalized scaffold weights, source/far mass ratios, convergence and
criticality of the amplitude series, the five- and eight-bridge constants (`eq:fiveconstant`, `eq:eightconstant`), the five-bridge code
entropy (`eq:fiveentropy`), the squared Catalan entropy, and all identities in `eq:Catnumbers`. The infinite-entropy conclusion uses Catalan
asymptotics in the proof, not a finite partial entropy sum.

## 5. Selector and moment suites (`ii-only/`, `renyi/`)

The `ii-only/` programs check all sixteen selector edges at depths zero, one and two, their separate Gram system, coordinate and counter
recursions, the exact equality readers, the reader norm 1/8, Boolean coordinates and the three-star construction. They also exercise the
injectivity hypothesis with a negative reader example.

The `renyi/` programs check weighted-tree moments, quarter-plane moments, comb rounding and normalizers, tail and truncation formulas,
Fibonacci reader bounds and the nested transport algebra. They do not test an arbitrary total verifier, and they do not prove a
computability classification from finite samples.

## 6. Capacity suite and the parity graph (`capacity/`)

Earlier versions of the paper contained a section on zero-error capacities; these scripts remain as checks of its finite
statements. `parity_certificates.py` enumerates all 16 384 vertex subsets of the fourteen-vertex magic-rectangle graph, all thirty-nine edge
orthogonalities, all 153 pairs of the eighteen-word block code, all forty-eight symmetry automorphisms and the full fourteen-dimensional
symbolic Fourier decomposition. It verifies the algebraic optimizer for Schrijver's number and every scalar or two-by-two positivity block.
The free-word telescoping identity and the coefficient 1/18 are exact. No Schrijver claim for the strong square is included. The bound
1/18 on the commuting loss is not sharp: Barouch Essayag and Zabokritskiy (arXiv:2610.12001) determine the exact commuting value of the
2x3 magic rectangle.

Separate numerical scripts test nonproduct saturation slicing, theta vectors, code scramblings and the rate identity. Their numerical
tolerances are reported in their logs. SDP values there are regression checks, not substitutes for the exact certificate.

## 7. Full reduction counts (`full-compile/`)

The directory holds the two word-stream generators, independent SQLite counters, small exact audits and count records. The optional
`--full-counts` run regenerates the word streams and prefix databases in the fresh result directory and reproduces the literal
6 191 638 087 and factored 8 516 580 question counts of the paper's size paragraph (Section 7). Neither run writes out a Boolean game. The
small audit checks the tree boundary loss t_m/(11616 Q^2) for depths zero through four and the associated rational layout accounting.

## 8. Labels inside the programs

Some program outputs use internal relation labels, for example "(19)-(21)" in the type suite or "(20) JK = ZKJ" in the tree checker.
`README.md` maps these labels to the paper. These finite-check labels do not identify proof-assistant results.

## 9. Nested compiler validation instances (`nested/`)

### 9.1 Parametric presentation input and exact size formulas

The general generator accepts a JSON presentation with typed `labels`, a list of `modular` names, and rational `relations`. Each relation is
a finite sum of coefficient/word pairs; a token ending in `*` is an adjoint. The generator checks the modular degree bound, splits all five
possible homogeneous degrees, adjoints negative degrees, and introduces the derived coefficients of the nested assembly (paper Appendix A).
It then writes the literal reduced words, proper prefixes, projection variables, rational rows and row plans. The general interface is

    python -I generate_nested.py --presentation INPUT.json --output-stem INSTANCE

The output stem must be a filename inside the chosen output directory. The two application schemas also accept supplied finite
cellular-automaton tables. The factored scan programs below avoid expanding a static track into a redundant product alphabet.

The word and rational-row schemas are written once to `compiler-schemas.json`. Let s count modular symbols; c the unitary encodings of
transported root labels and derived coefficients, two per contraction; r their projection labels; d the derived defining equations; and
p_app the final homogeneous application equations. Put a = 14 for the scaffold's bound parameters. Then

    g     = 24 + 6s + 3c
    p_str = 13 + 7s + 3c + r + d,      p = p_str + p_app
    V     = 15w + 1 - g + 19a
    R     = 12w - g + p + 17a - 1                                   (V1)

Here g counts unitary generators, V projection variables, R rational rows, and w words including the identity. The exact word count is
w = 1 + 2g + sum_{k>=2} n_k, where n_k is the number of distinct length-k reduced prefixes of the expanded input words. This prefix profile
is a size parameter of the presentation: a count using only the number and lengths of relations cannot account for shared prefixes.

To derive (V1): there are 9w graph rows, one frame row, one reference triangle, 2(w-1) placement triangles, w-1-2g proper-prefix product
triangles, g inverse triangles, 17a binding rows and p polynomial rows. Graphs use 12w projection names, triangles 3w-2-g, the frame three,
and parameter binding 19a. The outer transported list has 2+c+2s encodings, so the inner and outer bridge refinement counts per party are 6
and 8+c+2s.

### 9.2 The concrete programs and both decision branches

A tiny predicate family with indices e = 0, 1, 2:

    R(0,n,s) = false,     R(1,n,s) iff n = 0,     R(2,n,s) iff (n,s) = (0,0).                     (V2)

The first and third are NO instances of "exists n forall s R"; the second has the single integer witness n = 0. A predicate true at only one
pair has no witness that is universal in s. All three literal lists are generated, so this distinction is tested.

Each uniform verifier has eleven head states: none, boot, scan1, scan2, scanbig, move1, move2, movebig, accept, reject, wait. The return
marker is a separate immutable track. At the origin, boot becomes move1, ignoring the marker at zero. A move state clears its cell and sends
its scan state to the right. A scan on a nonmarker becomes the next saturated-count move state. At the first positive marker, scan2
certifies period 2 = F_3; scan1 and scanbig reject. For e = 1 period two accepts; for e = 0 it rejects; for e = 2 it waits one step and
rejects. Acceptance and rejection are absorbing. For these predicates every decoded n > 0 already fails at s = 0, so rejecting all other
periods is exactly the required specialization of the Fibonacci verifier.

The update rows are finite factored centralizer polynomials. With P_h the current head projection and L_h its left-neighbour copy, a
moving-head arrival is (I - Pi_x) L_{move j} P_none, where Pi_x is the boundary projection of the quarter-plane register (paper Section
10.1). For example N_move2 = (I - E_ret) P_scan1, and the positive instance has N_accept = P_accept + E_ret P_scan2. The none projection is
the identity minus all other successors. The code lists every successor polynomial. Their classical truth tables are deterministic even on
head collisions, using centre-state priority. Head projections have four synchronized neighbour/time families and the same endpoint
equations (`eq:nested-A4`) and initial boot/none rows. This representation is equivalent to a finite automaton with a static marker track,
and all its rows are in the admissible class.

For the comb take the two total programs k_m = 1 and k_m = m (V3). The constant program has critical index 0 and the linear program 1/2.
Both have nonzero B_0, B_1, branch vertices and leaves. Their six head states are none, boot, scan, move, accept, reject. The constant
program checks at x = 0 whether E_guard = 1_{l=0}. The linear program scans until the first M or L marker (encoding C_sp or L): the guard
should be one if the L marker occurs strictly first, and zero if the markers coincide or the M marker occurs first. Correct and
flipped-guard decisions are both checked. Every head family commutes with C_sp, L, E_guard, C_x, C_t.

In the legal linear comb, 0 <= l <= m, so the first marker is at x = l; the two stop cases are l < m and l = m. Before that cell both marker
bits are zero, giving a move followed by a scan one cell to the right. This proves termination and acceptance for every legal fibre by
induction, with no bound on m, l. Flipping the guard reverses the stop decision. As a negative control, the constant-depth comb is fed to
the linear checker: its fibres m >= 2, l = 1 then reject, and all other application identities still hold.

| Instance | g | w | p | V | R |
|---|---:|---:|---:|---:|---:|
| Uniform, never true | 201 | 6995 | 426 | 104991 | 84402 |
| Uniform, witness n = 0 | 201 | 6995 | 426 | 104991 | 84402 |
| Uniform, one true pair | 201 | 6995 | 426 | 104991 | 84402 |
| Comb, k_m = 1 | 171 | 8414 | 412 | 126306 | 101446 |
| Comb, k_m = m | 171 | 8583 | 412 | 128841 | 103474 |

These literal lists are validation instances. The general theorem rests on the parametric lemma, as in the compiler construction of the
paper's Section 4; the full reduction game for an arbitrary verifier program is not compiled.

### 9.3 Exact symbolic checks of the infinite models

The independent checker reads the exported JSON and does not import the generator. It substitutes graph, complement, tilted-graph, triangle
and binding formulas in the exact rational free group ring, treating parameter reflections as involutions. Every rational row other than an
input row becomes exactly zero. Every polynomial row becomes exactly its claimed pair of off-diagonal blocks, and every graph and triangle is
separately checked to be a projection. Semantic expression trees are independently re-expanded into the literal input polynomials, which
links the operator checks to the exported rows.

Every structural polynomial is also checked directly on all 25 scaffold corners, at generic basis coordinates and at each boundary. The
a_i and t unitary encodings are explicit monomial completions over the Gaussian rationals: on a source/range pair they are the swap with
phases 1, +-i, and on unmatched coordinates the phase is +-i. Root encodings are free diagonal phases keyed by basis coordinate; projection
encodings are involutions. This checks every support, axis, whole-activity block, reflection and t row, including unitarity of all
encodings. Positive and general diagonal contraction encodings can then be specialized by `eq:nested-N10`. The same structural identities
are checked again on rebuilt finite cutoff encodings.

Application checks use explicit decoded basis actions. S and T increment x and t, with adjoints vanishing at zero. On the comb basis (m,w),
V_sp increments m on the empty-word spine and vanishes off it, while B_i prepends i exactly when |w| < k_m; their adjoints remove the
matching prefix or vanish at the boundary. All counters, markers, guards and readers are the explicit scalar formulas of the paper. For the
period-two uniform models, Z = -I, J swaps two Weyl basis vectors, K = diag(1,-1), W = (-1)^x, and the reader is -2^{-x}/4 on odd x and
zero otherwise.

The checker evaluates the generic symbolic basis index and every lower boundary separately. Short tree words, both prefix bits, generic
opaque tails, spine boundaries, branch vertices and leaves are all included. Head fields are arbitrary symbolic functions for the endpoint
checks; their one-hot initialization and exhaustive local successor truth tables check the local update rule; the unbounded honest-history
recurrence is the induction written in the paper. The uniform programs have 5324 exact local update checks each and the comb programs 3456
each. The explicit period-two histories are also checked through the absorbing state. For the comb the two symbolic stop-order cases give a
zero rejecting projection on every legal fibre; this is a written induction, not a machine-checked induction certificate.

`check_far_history.py`, written independently of the row generator, evaluates all head-dependent exported application rows with
`cut=None`. For the linear comb it checks m, l <= 30 and t <= 65 (successor reads through 66), over 8.2 million row actions. This finite
far-index check supports the explicit history formula; it does not replace the unbounded induction.

**Nontrivial Fibonacci clock models.** A sparse complex checker evaluates the 187 exported application rows of `uniform-no` at clock orders
F_4, F_5, F_6 = 3, 5, 8, with a = 2, 3, 5 respectively and z = exp(2 pi i a / d_clk). It uses J|j> = |j+1 mod d_clk>, K|j> = z^{-j}|j>,
W(x) = z^x, and the complex reader of `eq:nested-A3`, conjugating diagonal values for adjoints. A separate evolution of the local rule
checks the explicit head history. The first positive marker is reached at time 2 d_clk; only the reject row is nonzero, on x = d_clk,
t >= 2 d_clk + 1. Its exact infinite root probability is 2^{-(3 d_clk + 2)}. All application rows are evaluated on both output corners, all
Weyl coordinates and all 0 <= x <= 2 d_clk + 1, 0 <= t <= 2 d_clk + 3. The rebuilt finite shifts have only the two source-isometry boundary
defects and this expected reject defect. These complex checks use tolerance 2e-12, not exact rational arithmetic. They allocate sparse basis
actions, stay below 1.5 GB, and do not write out a Boolean game. Value one as d_clk tends to infinity is a conclusion of the proof,
supported by these three finite models and the uniform analytic reader bound. The script is `check_fibonacci_models.py`.

A negative uniform instance has no perfect completeness model. The check confirms that only the expected rejecting row is nonzero. In the
generic symbolic pass, `reject_*` rows are skipped: for positive programs the formal reject field is assigned 0, so that pass does not
independently prove absence of rejection. The concrete far-index and finite truncation runs do evaluate the reject rows, including the
expected nonzero negative controls. With period two, the rejecting projection is x = 2, t >= 5 for e = 0, and x = 2, t >= 6 for e = 2.
Their exact root probabilities are 1/256 and 1/512. The wrong-guard comb control has root reject probability 1/256: the bad comb-fibre mass
is 1/4, the checker spatial mass 1/4, and the time tail 1/16. These exact values are the expected outcomes of the negative controls.

A binary-tree shift is locally finite in the word basis, but need not be banded under an arbitrary enumeration of vertices by one integer.
Polar completions are likewise specified by density blocks rather than by an assumed universal bandwidth. Explicit basis actions and exact
block formulas specify the checks. Finite shifts are tested with their boundary defects.

### 9.4 Finite defects, the worst rows and the loss bound

For a normalized geometric register on 0, ..., N put t_N = (2^{N+1} - 1)^{-1}. Covariance stays exact, while S_N^* S_N - I = -|N><N| has
weighted squared defect t_N. Its source lift has defect t_N/81 and its qutrit row 2 t_N/243. The isometry-row plans in these exports have
L = 8, d = 64. Consequently the total one-oriented boundary loss before the factor Q^{-2} is

    (t_{N_x} + t_{N_t}) / 124416                       (uniform)
    (t_{N_x} + t_{N_t} + 2^{-N_m}/Z_{N_m}) / 124416    (comb)                                     (V4)

Here every complete bush with m <= N_m is retained, and Z_N = 2(1 - 2^{-N}) for k_m = 1, Z_N = 3 - (N+3) 2^{-N} for k_m = m. Only the
two checker/register source-isometry rows and the top spine source-isometry row contribute boundary loss. All bush rows and all scaffold
rows remain exact. The worst boundary row is reported for each cutoff: in a balanced large linear comb it is a checker isometry, whereas for
the constant comb it is the spine row. All these defects are O(2^{-N}) for balanced cutoffs.

The forbidden-reject row has L = 2, d = 16, so a root rejecting probability p adds p/31104 before Q^{-2}. Thus a fixed-period negative
instance has a nonzero limiting reject defect, while its boundary defects tend to zero. The value-one construction separately sends the
chosen Fibonacci period to infinity, making the reject loss at most C_nest 2^{-d_clk}, as proved in the paper.

The rectangular cutoffs (0,0), (1,1), (2,3), (3,2), (7,3), (15,3), (31,7) and balanced cutoffs through 255 are evaluated by exact
normalized boundary formulas. Small cutoffs are also evaluated exhaustively for every application polynomial, with complete finite bushes.
For a general k_m <= m^2, keeping complete bushes still gives spine defect 2^{-N}/Z_N, and the omitted comb mass is at most
2^{-N}(N^2 + 4N + 7). Larger cutoffs are certified by these exact formulas; exponentially large matrices are never allocated.

### 9.5 Random algebra checks and the general regression

The random-algebra script runs 200 instance-independent random models of the nested transport and quadratic identities, in five batches of
forty; it uses no instance rows and no verifier program. Each model uses four full 32-dimensional corner spaces and unitary transports
between them; `eq:nested-N3` holds by construction. Five nilpotent modular contractions, complex corner gauges and density-eigenspace gauges
exercise the algebra. There are 145 checks per model, 29 000 in total, with maximum Frobenius residual below 7.1e-15 against tolerance
5e-12. Tiny density weights occur, but full-space corners and unitary transports make any test of dense-range support cancellation vacuous
here. This is an algebra check, not a game-to-operators soundness test.

A further synthetic input exercises all five modular degrees and all interior-coefficient translation routes, with three derived
coefficients. Its general compiler export has 43 197 words and 518 601 rational rows. The independent audit checks the row links and
projections, and exact rational 4-dimensional modular root matrices verify that each compiled residual is exactly the claimed transported
homogeneous residual, including the adjointed negative degrees. The regression presentation need not be satisfiable; the check tests the
translator.

The runner copies the generator and checking scripts to a new result directory, regenerates the large literal lists there, checks their
byte hashes and counts against the shipped records, and runs each audit from scratch. The large core JSON files are not shipped; the five
reference byte hashes are in `nested/expected-core-records.json`. No Boolean question/predicate table is written for any validation
instance: the exports contain the word lists, rational rows and row plans. Generated lists are finite certificates of their stated algebra,
not a game-to-operators soundness verification.
